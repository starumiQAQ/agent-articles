大语言模型在处理复杂的多步骤任务方面正变得越来越强大。推理、多模态和工具使用方面的进步，解锁了一类全新的大语言模型驱动系统——**智能体（agent）**。

本指南专为正在探索如何构建第一个智能体的产品和工程团队设计，将众多客户部署过程中的经验提炼为实用、可操作的最佳实践。内容包括：识别有前景用例的框架、设计智能体逻辑和编排的清晰模式，以及确保智能体安全、可预测且有效运行的最佳实践。

阅读本指南后，你将掌握开始构建第一个智能体所需的基础知识。

## 什么是智能体？（What is an agent?）

传统软件让用户能够简化和自动化工作流程，而**智能体能够以高度独立性代表用户执行同样的工作流程**。

> 智能体是能独立代表你完成任务的系统。

**工作流**是为了实现用户目标必须执行的一系列步骤——无论是解决客户服务问题、预订餐厅、提交代码变更，还是生成报告。

那些集成了 LLM 但**不**使用它们来控制工作流执行的应用程序——例如简单的聊天机器人、单次 LLM 调用或情感分类器——不属于智能体。

具体来说，一个智能体具备以下核心特征：

- 它利用 LLM 管理工作流执行和决策。它能识别工作流何时完成，并在需要时主动纠正自己的行动。失败时，它可以暂停执行并将控制权交还给用户。
- 它可以访问各种工具以与外部系统交互——既用于收集上下文，也用于采取行动——并根据工作流的当前状态动态选择合适的工具，始终在明确定义的护栏（guardrails）内操作。

## 何时应该构建智能体？

构建智能体需要重新思考你的系统如何做决策和处理复杂性。与传统自动化不同，智能体特别适合那些传统确定性和规则驱动方法无法应对的工作流。

以支付欺诈分析为例。传统规则引擎像检查清单一样工作，基于预设条件标记交易。相比之下，LLM 智能体更像一位经验丰富的调查员，评估上下文、考虑微妙模式，并在未违反明确规则的情况下识别可疑活动。这种细致入微的推理能力正是智能体能够有效管理复杂、模糊情境的原因。

在评估智能体可以增加价值的地方时，优先考虑那些**之前难以自动化**的工作流，尤其是传统方法遇到瓶颈的地方：

- **复杂决策**：涉及细致判断、异常处理或上下文感知推理的工作流
- **多步骤流程**：需要协调多个系统和步骤的工作流
- **非结构化数据处理**：涉及文本、图像或其他非结构化数据的工作流
- **适应性强的工作流**：需要根据用户输入或环境变化动态调整的工作流

## 智能体设计基础（Agent Design Foundations）

构建可靠的智能体需要几个关键组件协同工作。

### 模型（Models）

模型是智能体的核心。选择一个适合你需求的基础模型：

- **能力**：模型是否具备执行任务所需的推理、工具使用和指令跟随能力？
- **速度**：模型是否能满足你的延迟要求？
- **成本**：模型是否在预算范围内提供所需的质量？

OpenAI 的 GPT 系列模型（GPT-4o、GPT-4.5、GPT-5）在不同能力/成本权衡点上提供了多种选择。

### 工具（Tools）

工具是智能体与外部世界交互的接口。常见工具包括：

- **代码执行**：运行代码片段进行分析、计算或数据处理
- **文件搜索**：在文件系统中搜索和检索信息
- **网页搜索**：从互联网检索实时信息
- **函数调用**：调用外部 API 和服务
- **数据库查询**：从数据库中检索和操作数据

好的工具设计原则：
- 给工具起描述性的名称
- 提供清晰的参数和详细的描述
- 避免工具之间的功能重叠
- 从少数工具开始，根据需要增加

### 指令 / 提示（Instructions/Prompting）

清晰的指令对智能体的行为至关重要。有效的提示策略：

- **角色设定**：明确告诉智能体它是什么角色
- **约束条件**：定义什么可以做，什么不可以做
- **输出格式**：指定期望的输出结构
- **边界情况**：描述如何处理异常情况

### 智能体循环（Agent Loop / While Loop）

智能体的核心是一个简单的 while 循环：LLM 接收输入 → 决定下一步行动 → 执行行动 → 观察结果 → 继续循环，直到满足退出条件。

常见退出条件包括：工具调用完成、特定结构化输出、出错、或达到最大轮数。

例如，在 Agents SDK 中，智能体通过 `run()` 方法启动，循环执行直到以下任一情况发生：

- 调用"最终输出"工具（由特定输出类型定义）
- 模型返回无工具调用的响应（例如直接回复用户消息）

### 何时考虑创建多个智能体

我们的总体建议是**先最大化单个智能体的能力**。更多智能体可以提供直观的概念分离，但会引入额外的复杂性和开销，因此通常单个智能体配合足够多的工具就足够了。

对于许多复杂工作流，将提示词和工具拆分到多个智能体可以实现更好的性能和可扩展性。当你的智能体无法遵循复杂指令或持续选择错误的工具时，可能需要进一步划分系统并引入更多独立的智能体。

**拆分智能体的实用指南：**

- **复杂逻辑**：当提示词包含许多条件语句且提示模板难以扩展时，考虑将每个逻辑段划分到单独的智能体中
- **工具过载**：问题不在于工具的数量，而在于它们的相似性或重叠性。如果通过提供描述性名称、清晰参数和详细描述来改善工具清晰度后性能仍未提升，则使用多个智能体

## 多智能体系统（Multi-Agent Systems）

虽然多智能体系统可以根据特定工作流和需求以多种方式设计，但我们的客户经验突出了两个广泛适用的类别：

### 管理者模式（Manager / Agents as Tools）

一个中央"管理者"智能体通过工具调用协调多个专门的智能体，每个智能体处理特定任务或领域。

这种模式让一个中央 LLM（"管理者"）无缝地通过工具调用编排专门的智能体网络。管理者智能地将任务在合适的时间委派给合适的智能体，并轻松地将结果综合为一致的交互。

**适用场景**：只需要一个智能体控制工作流执行并访问用户的工作流。

### 去中心化模式（Decentralized / Handoffs）

多个智能体作为对等体运行，根据各自的专长将任务互相交接。交接是一种单向转移，允许一个智能体将工作委托给另一个智能体。

**适用场景**：不需要单个智能体保持中央控制或综合，而是允许每个智能体接管执行并根据需要与用户交互。

## 护栏（Guardrails）

护栏是确保智能体安全、可预测运行的关键组件。

### 基础护栏

- **输入验证**：在输入进入智能体之前进行验证和过滤
- **输出验证**：检查输出是否符合预期格式和内容要求
- **工具使用限制**：限制智能体可以使用的工具及使用方式

### 高级护栏

- **并发护栏**：在主智能体运行时并行运行的检查，可以在检测到违规时触发异常
- **失败阈值**：设置重试或操作次数的限制
- **高风险操作**：敏感、不可逆或高风险的操作应触发人工审核

### 人工干预计划

人工干预是一项关键的保障措施，可以在不影响用户体验的情况下提高智能体的实际性能。在部署早期尤为重要，有助于发现失败、发现边界情况并建立稳健的评估周期。

两种主要的触发条件：
1. **超过失败阈值**：设置智能体重试或行动的限制，超过后转交人工处理
2. **高风险操作**：取消订单、授权大额退款、支付等操作在获得足够信心前应触发人工监督

## 结论

智能体标志着工作流自动化的新时代——系统可以推理模糊情况、跨工具采取行动、并以高度自治处理多步骤任务。与简单的 LLM 应用不同，智能体端到端地执行工作流，使其非常适合涉及复杂决策、非结构化数据或脆弱的规则系统的用例。

要构建可靠的智能体，从坚实的基础开始：将能力强的模型与定义明确的工具和清晰、结构化的指令配对。使用与你复杂度水平匹配的编排模式，从单个智能体开始，只在需要时演进到多智能体系统。**护栏在每一个阶段都至关重要**——从输入过滤到工具使用再到人工介入——帮助确保智能体在生产中安全且可预测地运行。

成功部署的路径不是全有或全无。从小处着手，用真实用户验证，并随时间增长能力。有了正确的基础和迭代的方法，智能体可以交付真正的商业价值——不仅自动化任务，而且智能且适应性地自动化整个工作流。
